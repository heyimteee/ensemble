# Service subsystem map

[`src/v2/service.ts`](../../src/v2/service.ts) is the domain orchestrator behind the typed RPC in [`rpc.ts`](../../src/v2/rpc.ts). This page is a navigation index, not a second contract. Behavior and trade-offs stay in the [implementation notes](../implementation.md) and the ADRs linked below.

Read it before changing work lifecycle, delivery or retry, dispatch, handoffs, completion, batch review, native subagents, stream settlement, turn finalization, the store feed, the doctor, or the TUI boundary.

**Process shape.** [`server.ts`](../../src/v2/server.ts) attaches each OpenCode location through [`shared-service.ts`](../../src/v2/shared-service.ts); one service and store serve the host realm ([ADR 0003](../adr/0003-single-service-and-safe-recovery.md)). Maintenance is serialized and runs on a timer and before pump work; snapshot and scoped-read handlers are read-only ([ADR 0002](../adr/0002-durable-patch-feed.md)).

| Subsystem | Entry points | Invariants and owning contract |
| --- | --- | --- |
| Lifecycle and status derivation | [`queue.ts`](../../src/v2/queue.ts) `deriveWorkStatus`, `workNeedsYou`, `effectiveDeliveryHold`, `isDeliveryHoldRetry`; [`service.ts`](../../src/v2/service.ts) `overlayWorkStatus`, `pump`, `runTask` | One derived union: `pending`, `working`, `waiting`, `retrying`, `needs_you`, `replied`, `failed`, `stalled`, `cancelled`. Precedence is terminal, live lease or run, needs-you, waiting, retry, stalled, pending. `failed` is native-only; delivery, lease, and attempt exhaustion derive `stalled`. `Subtask.state` is storage compatibility, not the status. [ADR 0005](../adr/0005-work-status-and-delivery-lease-separation.md). |
| Retry and delivery holds | [`retry.ts`](../../src/v2/retry.ts) `retryDelayMs`, `nextRetryAttempt`, `RETRY_BACKOFF_MS`; [`queue.ts`](../../src/v2/queue.ts) `MAX_ATTEMPTS`, `LEASE_MS`, `HEARTBEAT_MS`, `DEADLINE_MS`; service `claimForRetry`, `reapAndRetire`, `reconcileWaitingWork`, `pump` | A retry needs structured failure evidence. The attempt cap, backoff schedule, lease, heartbeat, and delivery deadline are owned by those constants and helpers. Explicit retry or resume opens a fresh attempt budget. `deliveryHoldUntil` is a queued delivery, not a retry; only `retryAfter` is a retry. An unexpired claim is never stolen. [ADR 0005](../adr/0005-work-status-and-delivery-lease-separation.md). |
| Dispatch ledger | Pure arithmetic in [`dispatch-budget.ts`](../../src/v2/dispatch-budget.ts); serialized mutation in [`store.ts`](../../src/v2/store.ts) `admitDispatchedSubtask`; service `ensureDispatchGroupLedger`, `dispatchPreflight`, `refuseDispatch`, `noteContinuationCreated` | Four layers: command, group, task (`maxHops`), and depth. Admission, counter increments, and work creation are one serialized store mutation. Group state is derived from counters and closure, never stored. Only the leader opens a continuation, and only after the referenced group is exhausted. A refusal is a controlled `budget` stop, not a failed task. [ADR 0004](../adr/0004-dispatch-budgets-and-continuation.md). |
| Handoffs and completion hops | [`handoff.ts`](../../src/v2/handoff.ts) `parseHandoffFile`, `resolveHandoffRecipient`, `checkCompletionRoute`, `completionWorkKey`; service `toolHandoff`, `createPeerTurn`, `completionDeliveryLeader`, `ensureCompletionHandoff` | A handoff is a typed Markdown file under `.ensemble/handoffs/`, created through `ensemble_handoff` with a required `maxHops`. Idempotency keys (`work:`/`handoff:`) suppress duplicate work while the row is retained. Every ordinary non-leader turn owes one completion delivery to the leader; completion and batch hops are already terminal deliveries, and an explicit handoff satisfies the obligation. Completion hops, peer turns, synthesis, retries, recovery, and replays spend no hop; relay and failure legs are messages, not work rows. [Handoff contract](handoff.md), [ADR 0004](../adr/0004-dispatch-budgets-and-continuation.md). |
| Batch review | [`handoff.ts`](../../src/v2/handoff.ts) `groupCompletionCandidates`, `parseReviewDecisions`, `batchAllDecided`, `COMPLETION_QUIET_WINDOW_MS`; service `maybeConsolidateCompletionBatch`, `consolidateDueCompletionBatches`, `toolReview`, `applyReviewDecision`, `closeBatchReview`, `holdIncompleteBatchReview` | A batch is one group and one recipient, coalesced after the quiet window owned by `handoff.ts`. It closes only when every item is decided; a review turn with undecided items gets one correction turn, then stays open as needs-you rather than closing silently or running its items. `delegate` requires a real recipient. [Handoff contract](handoff.md), [work lifecycle](../implementation.md#v7-work-lifecycle-and-recovery-model). |
| Native subagents | [`native-subagents.ts`](../../src/v2/native-subagents.ts) limits, `NATIVE_SUBAGENT_BARRIER_MS`, `NATIVE_SUBAGENT_WAKEUP_GRACE_MS`, and state helpers; service `handleNativeSubagentCreated`, `handleNativeSubagentExecution`, `handleNativeSubagentIdle`, `handleNativeSubagentDeleted`, `awaitNativeSubagentBarrier`, `awaitNativeWakeup`, `settleNativeAnswer`, `reconcileLateNativeFollowUp` | A native child is a durable `NativeSubagentRun` keyed by `childSessionID`, not a Subtask: it never enters the queue and spends no hop. First terminal state wins. A successful parent holds its live lease until the child is terminal or the barrier expires, then waits for the post-child answer within the wake-up grace. A late follow-up is appended and delivered exactly once by native message identity plus a durable task marker; arbitrary native chat is never mirrored. Logs carry IDs, states, sources, counts, and durations only. [Native subagent verification](../verification/2026-11-09-subagent-live.md), [core turn reliability](../verification/2026-11-10-core-turn-reliability.md), [implementation](../implementation.md#workspace-shell). |
| Stream settlement | [`stream-settlement.ts`](../../src/v2/stream-settlement.ts) `isSubstantiveReply`, `shouldInterruptSettledReply`, `planLateSuccessRepair`; service `settleStreamMessage`, `streamFinalization`, `finalizeStream`, `settleTerminalStreams` | `Reply interrupted.` is reserved for a genuine host interruption, an empty or fallback stream, or a real native failure. Delivery, lease, retry, and stall states preserve a substantive answer. Checkpoints are version-neutral; finalization persists once and publishes one exact durable upsert that replaces the live overlay once. A late success repairs a placeholder and never overwrites a substantive row. [ADR 0002](../adr/0002-durable-patch-feed.md), [ADR 0005](../adr/0005-work-status-and-delivery-lease-separation.md). |
| Turn finalization | [`turn-finalization.ts`](../../src/v2/turn-finalization.ts) `decideTurnFinalization`; service `turnFinalizationFacts` and the terminal path in `runTask` | One pure policy decides accept, wait, correct, or warn. A live native child holds the turn. A batch review with undecided items gets one correction, then a visible warning. A member mentioned without backing work gets one correction, then a visible warning. Durable markers prevent a second correction after retry or restart. All side effects stay in the service. [Core turn reliability](../verification/2026-11-10-core-turn-reliability.md). |
| Store and feed | [`store.ts`](../../src/v2/store.ts) serialized writes, `snapshot`, `changesSince`, `publishPending`, `sync`; [`scoped-read.ts`](../../src/v2/scoped-read.ts); [`tui/client-store.ts`](../../src/v2/tui/client-store.ts) | The server store is the sole source of truth and the client is disposable. Durability precedes publication. One epoch and one monotonic version; patches are full-entity and idempotent. A gap, epoch change, malformed batch, or evicted cursor ends in scoped resync or full snapshot, never silent stale state. Scoped reads and windows are gated projections. Read handlers do not write. Claim fields are process-local; `sync()` never overwrites a locally held claim. [ADR 0002](../adr/0002-durable-patch-feed.md), [ADR 0003](../adr/0003-single-service-and-safe-recovery.md). |
| Doctor | [`doctor.ts`](../../src/v2/doctor.ts) `diagnoseLocations`; [`doctor-cli.ts`](../../src/v2/doctor-cli.ts), `npm run doctor`; service `diagnostic` | Read-only and one selected service at a time, not an atomic cluster probe. It checks config, membership, bindings, lifecycle contradictions, ledger caps and counters, continuation lineage, and native child records. Differences are diagnostic evidence, not automatic proof of a stale process. [Runtime guide](opencode-tui-runtime.md#locations-services-and-storage), [doctor reference](../../README.md#runtime-diagnosis). |
| TUI boundary | [`rpc.ts`](../../src/v2/rpc.ts) `EnsembleV2Rpc`; [`server.ts`](../../src/v2/server.ts); [`tui/app.tsx`](../../src/v2/tui/app.tsx); [`tui/client-store.ts`](../../src/v2/tui/client-store.ts) | The TUI page does not import service internals. Reads come from snapshot, bootstrap, transcript window, and the patch feed; actions go through the typed RPC. The client applies idempotent entity updates, keeps bounded transcript and Work memory, and treats a feed gap as a resync signal. It consumes `deriveWorkStatus` instead of inventing a second status. A TUI module move requires a full client restart, not only a service restart. [Runtime guide](opencode-tui-runtime.md), [ADR 0002](../adr/0002-durable-patch-feed.md), [ADR 0006](../adr/0006-three-pane-workspace-shell.md), [ADR 0008](../adr/0008-task-level-history-and-rollup.md). |

If this map and the code disagree, the ADR or implementation note wins; update the map in the same change.
