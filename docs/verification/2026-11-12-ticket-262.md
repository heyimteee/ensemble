## docs:check behavior

The check exits `1` and names the file for any of these stale or missing
claims:

- A `contract vN` claim that is not the current block version (README).
- A bold `OpenCode **X**` claim outside the supported host set (README).
- A `Node X+` or `Node X or newer` floor that is not `22.23.4`.
- A missing current README/implementation/ADR/host-range claim.
- A current verification record (dated 2026-11-11 or later) that is not linked
  from `docs/README.md`.
- `package.json` `engines.node` or a CI matrix that disagrees with the
  canonical constants.

It exits `0` with one line naming the current contract, hosts, Node floor, and
live Node line. It exits `2` for usage errors. It reads relative paths only;
it prints no absolute paths, conversation content, credentials, or file bytes.

`src/v2/docs-check.test.ts` runs the CLI against a temporary copy of the docs
and asserts that the current tree passes, a stale contract claim fails, a stale
Node floor fails, an untested host fails, and an unlinked current record fails.

run inside `npm run verify` through the normal `src/v2/*.test.ts` glob.
