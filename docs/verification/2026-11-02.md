## What each check proves

- **Universal wizard navigation.** The fake scenario opens the New-agent wizard and asserts the footer reads `Ctrl+N next` and `Ctrl+P back`, then sends `Ctrl+N` (pane advances to `Agent title`) and `Ctrl+P` (returns to `Agent name`). The wizard layer binds `ctrl+n` / `ctrl+p` directly and is deliberately not wrapped in the platform Ctrl→Cmd transform, because stock macOS terminals never deliver Cmd chords; unit tests pin the constants and prove the generic transform *would* rewrite them, documenting why the bypass must stay. The searchable help applies the same exemption so those two entries stay truthful on macOS while other app shortcuts still show Cmd.
- **Live model options and explained empty state.** Unit tests cover option derivation from a changing catalog, option equality, choice preservation/fallback, and the empty-state copy. The fake scenario (one model configured) walks to `Main model` and continues. The new empty-catalog scenario (`models: {}`) asserts `0 options` plus `No models available …` on the model step and that Escape still cancels the wizard; the catalog's failure reason reaches the snapshot through a new optional `modelsError` field. Service tests prove the field is populated for both an empty and a failing catalog and that credential-shaped text (keyword pairs, Bearer tokens, `sk-` keys) in the host error is redacted. The empty explanation is gated on the catalog's option count, not the filter result, so filtering a healthy catalog never claims a catalog failure.
- **Snapshot output contract.** Live runs initially failed with `rpc.invalid_output: Expected string at ["configError"]`: the host RPC validator rejects optional fields present with `undefined`. The snapshot payload now omits absent optional fields instead of serializing them as undefined; that fixed the live RPC and keeps the schema honest.
- **Centered overlay.** Unit tests cover the shared geometry helper: bounded width (48–96), horizontal and vertical centering, and recomputation for a changed viewport. The wizard overlay reads renderer dimensions from a resize-fed signal, so it recenters after a renderer resize; content stays left-aligned and the hint row is horizontally centered inside the box. The live checks assert text and behavior, not pixel positions.
- **Help consistency.** The searchable help lists `Ctrl+P` / `Ctrl+N` for wizard steps; the help test asserts the new tokens.

## Cleanup and data safety

Both fake scenarios isolate HOME and XDG directories, use the loopback fake provider with no API key, and clean their temporary directories and tmux sessions on success. No real workspace data was read or modified by the live checks. `npm run test:live` uses the harness's isolated project/HOME as before.

## Remaining uncertainty

- No live macOS run: the Ctrl+letter family is the only one stock macOS terminals reliably deliver, but terminal-specific overrides (kitty protocol, custom key bindings) are outside this verification.
- Centering is verified through the geometry helper plus behavior, not pixel-level pane captures; extremely small viewports are clamped to the 48-column floor and may still hide some content by design.
- The empty-catalog scenario proves the product's empty state; the reporter's original empty catalog on their machine may also have had a provider configuration cause, which this work explains but does not repair.

## What each check proves

- **Durable DM transcript (unit).** New `src/v2/dm.ts` seam: `mapNativeChat` keeps only non-empty user/assistant text; `mergeDmTranscript` treats stored per-binding lines as authoritative for `role: "user"` (native user content — echoes, onboarding steer prompts — never renders), keeps native assistant replies, preserves queued flags, and sorts stably by `(createdAt, user-first, id)`. Five `dm.test.ts` cases pin the merge, including the phantom-line and exactly-once cases. `chat.send` now appends the user line to the `v2/dm/<workspaceKey>/<agentID>/` store synchronously at send time (monotonic per-service clock so same-millisecond sends keep order), reusing the same id for the `dmQueue` entry; `flushDmQueue` clears the queued flag on send/fail; `moveHome` migrates the transcript; agent deletion prunes it; `pruneWorkspace`/`reset` remove it. Service tests prove: the line renders immediately; it survives a restart through the store load path with a native echo present (exactly `["Persist me", "OK"]`); a queued-while-busy line stays visible with `queued: true` then clears; store tests prove reload ordering and pruning.
- **Leader routing (unit + handler).** `routing.test.ts` pins total routing: unmentioned → leader only, single mention replaces default, fan-out → exactly the mentioned, archived members excluded, unknown names reported via `unknownMentions`. Service tests prove an unmentioned `message.send` creates exactly one subtask assigned to the leader with the existing system line `→ Nova: <title>` intact, and that routing ignores recent activity (after `$Sage` work, an unmentioned message still routes to Nova). `lastActiveAt` was audited: written for rail ordering/unread counts, never read by `visibleRecipients`/`sendMessage`/`createSubtask`.
- **Routing observability without redesign.** Group-chat surface title now reads `#name · dir · leader <Name>`; `ensemble_workspace_info` / `ensemble_list_workspaces` return the leader and members as `{id, name}` pairs (plus `synthesis` on workspace_info); `/init`, `Shift+I`, and the shortcut help now label workspace initialisation as initialisation, not routing (`Init workspace files (initialisation, not routing)`). No init semantics changed.
- **Wizard exclusive focus + Enter (unit + live).** `openWizard` now closes the completion popup, blurs and deactivates the composer, and every competing key layer (`global`, composer-cancel, completion, settings, approvals, help) additionally requires `wizard() === null`. Enter on non-text steps routes through the new pure `wizardEnterAction(kind, final)` helper (`select`/`continue`/`submit`/`text`, unit-tested in `wizard.test.ts`); the handler closes completion, owns Enter on choice/pick/multi including the final step, and text steps still return early to the field (`Enter` = continue, `Shift+Enter` = newline). The fake live scenario walks the full workspace wizard (`n`, directory Enter, name type + Enter, members Enter = continue, leader Enter, synthesis `Yes` Enter) and asserts `#LiveSite` appears, the surface reads `leader FakeAgent`, the snapshot persists `synthesis: true`, `$ agents` (completion title) never appears, and the DM user line `fake-rich-fixture` renders exactly once. The fake provider already answers every DM prompt (short reply / rich fixture), so the DM send completes in-scenario.
- **Untouched surfaces.** `test:live:fake:empty` still passes (catalog/model-step behavior unchanged); the real-model `test:live` passes with no new assertions affected.

## Cleanup and data safety
