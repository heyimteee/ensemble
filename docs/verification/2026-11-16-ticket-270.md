## Scope

This record covers the `0.1.0-rc.1` clean-install proof only: packing the
candidate, serving it from a loopback-only npm registry, installing it with
`opencode plugin add` into an isolated OpenCode 2.2.7 host, and checking the
installed package source, server tools, and TUI route/command. No public npm
publish, real credential, workspace link, or repository plugin path is used.
The OpenCode configuration, HOME, XDG directories, project, and mock agent are
temporary and were not the user's global configuration.

## Command

```sh
npm run test:install:rc
```

This runs `scripts/live-install-check.sh`. The script packs the candidate,
starts `scripts/lib/local-npm-registry.mjs` on a loopback port, writes an
isolated `.npmrc`, runs `opencode plugin add @heyimteee/ensemble@0.1.0-rc.1`,
checks `opencode plugin list`, starts the isolated fake provider and server,
drives one host turn, then starts the isolated TUI and opens `/ensemble`.
`src/v2/local-npm-registry.test.ts` covers the loopback registry's packument
and tarball seam inside `npm run verify`, so a route regression cannot silently
break the installer integrity check.

## TUI failure

The isolated TUI shows `Plugin failed: @heyimteee/ensemble@0.1.0-rc.1`, and its
log reports:

```text
plugin operation failed ... stage=load
error="Cannot find package 'react' imported from
<isolated-cache>/cache/opencode/npm/@heyimteee/ensemble@0.1.0-rc.1/<install>/node_modules/@heyimteee/ensemble/src/v2/tui/index.tsx"
```

The installed source package has no `tsconfig.json`, so the host loader uses
the classic JSX runtime and asks for `react`. In a throwaway copy of the
installed package, adding `@jsxImportSource @opentui/solid` to the three TSX
entries moved the failure to:

```text
error="Cannot find package '@opentui/solid' imported from
<isolated-cache>/.../src/v2/tui/index.tsx"
```

The optional peers `@opentui/core`, `@opentui/solid`, and `solid-js` are not in
the plugin cache. The source package therefore cannot load its TUI part from
the real install location even though the same files load from a checkout with
the repository `tsconfig.json` and `node_modules`.

Per the ticket, the source package was not replaced silently with a built
package and no success is claimed. Follow-up
[#279](https://github.com/heyimteee/ensemble/issues/279) covers the built
server/TUI artifact, bundled or declared TUI runtime dependencies, a runtime-only
pack allowlist for built files, and a fresh `0.1.0-rc.2` clean-install proof.
