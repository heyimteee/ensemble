## Behavior

`nativeFirst: "shadow"` now runs the #215/#216 turn semantics into an
invisible, in-memory sink:

- inbox/text/execution events create shadow turns and text parts using the
  same deterministic turn, user-message, and assistant-message identities;
- the pure #219 planner computes the routes that would be admitted, but no
  ledger is opened, no peer turn is created, and no refusal is posted;
- no durable message or turn is written, no patch/stream frame is published,
  and no Work card appears;
- at settlement the sink reads the native transcript once to compare the
  shadow final text with the visible path, then records a bounded comparison
  row and clears the in-memory turn/session state.

`off` and `on` are unchanged: `off` ingests nothing, `on` is the cutover path.

## Comparison record

`native.shadow.compare` carries IDs, channel kind, text length and
`stableHash` digest pairs, shadow/expected phase, visible-turn presence, planned
user/final route counts, visible route count, and match booleans. It never
carries message text, prompt text, file bytes, or paths. In-memory comparison
history is bounded to 32 rows and exposed as
`diagnostic.native.shadow.last`; it is cleared on service stop/restart.

## Safety

- Shadow mode cannot publish durable entity changes by construction: it never
  calls a store writer, scheduler, or router.
- Shadow state is cleared on settle, mode change, service stop, and restart.
- Service prompt content never appears in shadow logs or diagnostic rows.
