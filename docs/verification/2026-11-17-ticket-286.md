# OpenCode 2.3.0 compatibility

Ticket [#286](https://github.com/heyimteee/ensemble/issues/286). This record
covers the host-range expansion from `2.2.6 || 2.2.7` to
`2.2.6 || 2.2.7 || 2.3.0`.

## Environment

| Item | Value |
|---|---|
| Base | `4ccc410` (`ticket/286-opencode-230`) |
| Platform | Linux/tmux 3.5a |
| Node | 26.12.1 |
| OpenCode | 2.3.0 and 2.2.7 |
| Isolation | `scripts/lib/live-harness.sh`; fresh HOME/XDG roots, project, workspace, fake provider, and host per run |

## Scope

The runtime behavior is unchanged. The host contract probe on 2.3.0 passes
every check; the only pre-existing failure was the version gate. The
deterministic fake E2E exposed one host-theme difference: focused headings and
borders use the host's high-contrast text tone (`#eeeeee`, SGR
`38;2;238;238;238`) instead of exact white. The harness now accepts both tones
for focus while keeping unfocused grey distinct.

The fake runs use the committed fake provider only; no real model catalog and
no network model calls are involved. The probe writes a sanitized JSONL record
to a temporary path and does not refresh the committed 2.2.6 fixture.

## CI contract

- `.github/workflows/compatibility.yml` runs the host probe and deterministic
  fake smoke for `2.2.6`, `2.2.7`, and `2.3.0`.
- `REQUIRED_STATUS_CHECKS` and `docs/operations/release.md` include
  `OpenCode 2.3.0`; the ruleset must add that context after merge.
- `verify.yml` and `nightly.yml` pin `OPENCODE_VERSION: "2.3.0"` because the
  contract checker requires the latest supported host. `2.2.6` and `2.2.7`
  remain supported and in the compatibility matrix.

## Remaining limitations

- macOS/Herdr remains unverified by ticket #277; this record is Linux/tmux
  evidence only.
- OpenCode releases newer than `2.3.0` remain untested and load with the
  runtime warning.
- The committed native host fixture remains the 2.2.6 recording; the 2.3.0
  probe matched the same contract and was not written over it.
