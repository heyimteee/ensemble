This is the specification-level verification record for v6. It covers the nine
motion scenes, the Work-card size matrix, the one/two/three-card load probe,
reduced motion, `NO_COLOR`, and the automated regression gates. It does not
close #113 or #127. The [macOS/Herdr checklist](macos-herdr-checklist.md)
remains manual and unexecuted.

**Linux/tmux is not macOS/Herdr evidence.** Everything below was observed on
Linux with tmux. No macOS/Herdr host ran any part of this pass, so Braille font
coverage, Herdr key interception, native-session key ownership, toast
appearance, and actual color/opacity rendering on macOS remain unverified.

## Work-card size matrix

`npm run test:live:sizes` starts the isolated fake host, creates three agents
and one workspace, and restarts the TUI at each geometry with
`ENSEMBLE_LIVE_TUI_WIDTH`/`ENSEMBLE_LIVE_TUI_HEIGHT`. At each size it delegates
one `fake-queue-hold` task per agent, waits for `WORK 3 active`, and checks the
header, visible cards, overflow, focus cursor, and composer.

| Size | Layout observed | Assertions | Result |
|---|---|---|---|
| 80×24 | Compact fallback: one one-line row, `+2 more`, no card headers or card hint row | Header `WORK 3 active · 0 recent │ +2 more`; compact row `size-80x24-a │ SizeAgent1 │ working`; cursor `›` on that row after `Tab`; `Esc` returns `NORMAL  │ Group chat`; composer `Message…` visible | pass |
| 100×30 | Card mode: one full card, `+2 more` | Three active tasks exceed the card-height budget, so `workCardLayout` renders one card; card hint row present; cursor `›` on the first card; composer visible | pass |
| 120×40 | Card mode: three cards, no overflow | Three Work card headers, no `+N more`, card hint row, cursor on the first card, `Esc` returns to group chat, composer visible | pass |
| 160×50 | Card mode: three cards, no overflow | Same card checks as 120×40 | pass |

The 100×30 result is the implemented height policy, not a skipped check: three
active cards cannot fit the available rows, so one card plus `+2 more` is
shown. Two active tasks at 30 rows fit two cards (covered by
`workrows.test.ts` and by the layout rule).

An exploratory run of the **full** `test:live:fake` scenario at 120×40 stopped
at the existing `finalized rich reply` assertion because the shorter viewport
did not show the `Rich Markdown Fixture` heading. That scenario is calibrated
for its 160×80 default and its transcript assertions are viewport-sensitive;
the targeted size matrix above is the size evidence. The toast placement
assertion in the full scenario was made width-relative in this ticket because
the scenario is size-parameterized.

## Known limitations and residual risks

- **No macOS/Herdr evidence.** Braille font coverage, Herdr key interception,
  native-session key ownership, toast appearance, and actual color/opacity
  rendering were not observed on macOS. The checklist is extended for v6 and
  marked unexecuted.
- **Text capture is not visual verification.** The record observes glyphs,
  labels, counts, and layout text. It does not prove exact color, contrast,
  opacity, anti-aliasing, or smoothness, and no screenshots were captured.
- **The full fake scenario remains 160×80-calibrated.** At 80×24 and 100×30 the
  targeted size script covers Work layout, focus, overflow, and the composer,
  not all nine scenes. The 120×40 exploratory full-scenario failure is recorded
  above.
- **CPU samples are noisy.** They are one 0.9s sample per card count on this
  host, exclude the server process, and have no threshold.
- **Recent-card boundary.** The eight-second constant and boundary are
  unit-tested; the live suite observes the recent window close, not the exact
  millisecond boundary. The size script waits out the window before each
  restart.
- **Tide variety is unit-tested more strongly than live.** The fake suite
  observes Braille animation and Work-card tide rows; the six-variant
  shuffle-bag, distinct fixed-width strips, and stable per-subtask assignment
  are proven in `tide.test.ts` and `workrows.test.ts`, not enumerated live.
- **Toast size coverage.** The live toast placement check runs at the default
  160×80 geometry. The size matrix does not trigger a toast at 80×24/100×30.
- **Hosted CI was not run.** The local gates above passed; no GitHub Actions
  run is claimed.
