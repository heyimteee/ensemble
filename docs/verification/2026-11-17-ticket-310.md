## Docs contract

`npm run docs:check` now validates:

- the required page inventory and every user page's reachability from its
  section index;
- title, description, version scope, and H1/title agreement on every
  user-facing page, including historical release pages with their own version;
- every internal Markdown link and heading anchor across `docs/` and the root
  Markdown files, plus raw HTML links in the README;
- balanced code fences, a language on user-page fences, and `bash -n` syntax on
  every `sh`/`bash` block with style-guide placeholders substituted;
- canonical package, contract, host, and Node claims, including install
  versions and the site's stable-version label;
- generated-reference freshness, media, evidence-index links, and the VitePress
  docs-site build.

The default command runs the site build. Unit fixtures use the explicit
`--skip-site-build` internal mode so a VitePress build does not run dozens of
times inside the unit suite. CI runs the full default. A missing required page,
link, anchor, or frontmatter field is a validation failure (exit 1), not an
uncaught error; regression fixtures cover that distinction.

## Quickstart E2E

`npm run test:live:quickstart` packs the package, serves only
`@heyimteee/ensemble` from a loopback registry, installs it with
`opencode plugin add`, and checks the installed `dist` entry and runtime
dependency resolution in the isolated plugin cache. It then drives the TUI:

1. `/ensemble` reaches the empty `ENSEMBLE` page.
2. The agent wizard creates **Nova** and then **Rook**.
3. The workspace wizard creates `acme-notes` with both agents and Nova as
   leader; both move-home prompts are accepted.
4. The composer sends the first group message.
5. The Work pane shows the card and settles it as `REPLIED`; the durable
   snapshot contains one matching replied work item.

The local registry, pack, isolated HOME/XDG directories, and fake provider are
harness setup. Every product transition above was driven and observed through
the TUI. The synthetic screenshot/replay fixture from #309 is not this proof.

## CI and PR guard

- `.github/workflows/docs.yml` installs dependencies and runs the full
  `npm run docs:check`, including the site build, as a separate docs job.
- `verify.yml` `live-fake` owns `test:live:quickstart`; the CI job-graph test
  asserts the suite belongs to exactly that job.
- `.github/workflows/docs-rationale.yml` runs on `pull_request_target`, checks
  out the trusted base commit with `persist-credentials: false`, requests only
  `contents: read` and `pull-requests: read`, reads the PR body and changed-file
  list as data, and never executes pull-request code or reads secrets.
- `scripts/docs-rationale.mjs` requires a docs update or a
  `docs-not-needed: <reason>` line for user-visible source changes. Test-only,
  workflow, and docs-tooling changes are explicit exemptions. Empty rationales
  fail.

## Limits and exclusions

- The 29-second figure measures the automated packed-install path. Install,
  npm registry, and scripted typing latency can differ for a human; this record
  does not convert the smoke into a human usability result.
- macOS, Herdr, screen capture, pointer interaction, browser axe, and real-model
  checks were not rerun for this ticket. The #309 browser/accessibility record
  remains the evidence for that layer.
- The repository development tree's `npm ci` audit output (34 advisories:
  2 low, 27 moderate, 1 high, 4 critical) is not a consumer package security
  claim. No dependency or audit result was changed here.
- The blocked #296 upgrade work was not cherry-picked or merged; no unrelated
  dependency or runtime change is included.
- This branch adds the `docs-rationale` workflow job but does not change the
  repository ruleset or mark it as a required status check. A maintainer must
  do that separately after merge if the policy requires it; the job itself
  fails the PR run when the rule is violated.
- Historical verification records are public evidence and were not rewritten.
  They contain pre-existing developer workspace paths; this ticket adds no new
  private path, credential, conversation, or real user data.
