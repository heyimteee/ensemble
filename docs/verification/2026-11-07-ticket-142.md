## Static/motion split

- `workCardForTask` now returns identity-only `WorkCard` data: header layout,
  title, detail, status, needs-you, terminal, tones, tide variant, and content
  width. It accepts no animation tick or process env.
- `workCardGlyph` reads only the 4 fps chrome tick; `workCardTide` reads only
  the 10 fps work tick (plus the existing needs-you freeze state). Terminal
  cards stay flat without reading either clock.
- `workCardForTaskCached` keeps the previous card reference when every
  identity field is value-equal. `workPane` no longer reads `motionFrame()` or
  `workFrame()`, so a tick cannot rebuild titles, names, details, statuses,
  tones, or layout.
- `WorkCardView` receives `glyph` and `tide` as separate reactive props. Its
  header computation tracks only the glyph clock; its tide row tracks only the
  work clock.
- Reduced motion continues to pin both clocks to frame zero through the
  existing `effectiveTick`/`shouldRunWorkClock` gates; the still frame is
  verified live with `NO_COLOR=1`.

## Group hold and status expiry

Removing the animation clocks from `workPane` would have frozen the #136
1.2 s group hold and derived deadline/lease transitions. A dedicated one-shot
timer now invalidates the static pane at the earliest of:

- a non-terminal task's `deadlineAt`,
- a working task's `leaseUntil`,
- a complete group's `latestTerminalAt + 1.2 s` hold.

`nextWorkInvalidation` is pure and unit-tested. It is not an animation clock
and does not rebuild glyph or tide data. Needs-you freeze frames for visible
cards are refreshed during static invalidation, because a needs-you card stops
the 10 fps clock and otherwise would age out after 8 s.
