## State shape

`src/v2/native-state.ts` now owns one `NativeSessionState` per session in one
map. The value owns enqueue order, pending inboxes, execution owner,
answer-ordered execution turns, steered inboxes, the settled run id, the active
turn, reordered execution starts, assistant-message mapping, text parts, live
row checkpoints, the watchdog, delivery state, and deferred child settlement.

Mutations go through named transitions:

- `enqueue` — host order, pending queue, reordered execution starts;
- `start` / `joinExecution` — execution owner and participants;
- `answer` — text parts and assistant-message identity;
- `steer` — delivered-into-a-running-execution candidates;
- `settle` — execution participants, per-turn memory, owner, and inbox slots;
- `reconcile` — adoption re-queue and watchdog re-arm;
- `deleteTurn` / `deleteSession` — per-turn and per-session release.

The service keeps only `nativeQueues` (event serialization) and
`nativeReconcileRuns` (coalesced reconcile) as async gates. The native
subagent maps are a separate subsystem and are unchanged.

## Maps removed

`nativePendingInboxes`, `nativeInboxOrder`, `nativeExecutionOwner`,
`nativeExecutionTurns`, `nativeSteeredInboxes`, `nativeRunSettled`,
`nativeActiveTurn`, `nativePendingExecutions`, `nativeAssistantTurns`,
`nativeText`, `nativeRows`, `nativeWatchdog`, `nativeDeferredSettlements`, and
`nativeDelivery`. Every former call site reads `nativeState.peek(sessionID)` or
mutates through a transition.

## Tests

`src/v2/native-state.test.ts` adds a table test per host event family:
`session.inbox.enqueued`, `session.inbox.delivered`,
`session.inbox.cancelled`, `session.text.started/delta/ended`,
`session.retry.scheduled`, `session.execution.started`,
`session.execution.succeeded/failed/interrupted`, plus adoption, turn deletion,
and session deletion.

The existing #215–#229 native ingestion, retry, interruption, steering,
adoption, watchdog, barrier, and restart suites pass unchanged. No behavior
test was rewritten.

## Behavior notes

No observable behavior change. Two in-memory details differ only in lifetime:

- an empty per-session value persists until service stop instead of individual
  maps deleting empty entries; no read path distinguishes the two;
- service stop now clears every native in-memory value (the old stop left text,
  pending, active, assistant, and delivery maps behind). The service is already
  stopped at that point.
