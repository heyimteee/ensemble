This record covers the visual layer for the VitePress documentation site: the
terminal replay, six screenshots, Mermaid rendering, alt text and captions, and

**Acme Notes** fixture. No real screen, display, browser tab, conversation,
credential, or user path was read.

## Generated media

`npm run docs:media` starts only the fake provider and a temporary OpenCode
host through the existing live harness, creates the synthetic workspace through
the real RPC surface, captures the actual TUI with `tmux capture-pane -e`,
renders the images, and writes the asciinema v2 cast. The temporary project path
is redacted to `~/dev/acme-notes` with same-width padding so later columns do
not shift. The renderer rejects `/home/`, `/tmp/opencode/`, the current user
name, and fixture markers before writing.

| Asset | Natural size | Purpose |
|---|---:|---|
| `docs/public/media/workspace-shell.png` | 1100×680 | Three panes with an active Work card |
| `docs/public/media/work-active.png` | 742×510 | ACTIVE Work pane, one WORKING card |
| `docs/public/media/work-history.png` | 742×510 | HISTORY pane with rolled-up groups and an expanded REPLIED card |
| `docs/public/media/approvals.png` | 742×510 | Full approvals inbox with one pending Memory approval |
| `docs/public/media/settings.png` | 700×930 | Ada settings, General tab |
| `docs/public/media/native-session.png` | 1100×680 | Ada's native session with the synthetic reply |
| `docs/public/media/hero-terminal.cast` | 110×34, 6 frames | asciinema v2 replay |

`docs/public/media/MANIFEST.json` records the SHA-256 and dimensions of every
asset. `npm run docs:media:check` verifies the hashes, all `DocsFigure` paths,
non-empty alt text, captions, the terminal-hero poster description and text
summary, Mermaid `accTitle`/`accDescr`, and user-page heading order.

The fixture and visible UI states are deterministic, but elapsed-time labels,
stream-phase glyphs, and the native Build durations are rendered by the host and
can differ between regenerations. The manifest records the committed bytes so
the docs check detects a stale file rather than claiming byte-identical replay.

The replay assets are a **scripted replay**: the install command is typed at a
real isolated shell prompt but is deliberately not executed; the workspace,
message, Work card, and native session frames are captured from the local fake
host. The page caption and disclosure say so. The cast is assembled from those
captured frames rather than recorded by the `asciinema` CLI; it is a valid
asciinema v2 file and is played by the locally bundled `asciinema-player`.

## Mermaid

Five diagrams render as SVG with `accTitle`/`accDescr` exposed as the SVG
`title`/`desc` and `role="graphics-document document"`:

- `concepts/architecture`: Ensemble architecture.
- `concepts/workspace-shell`: three-pane shell.
- `concepts/work-lifecycle`: ACTIVE and terminal lifecycle.
- `concepts/dispatch-budgets`: budget layers and continuation paths.
- `concepts/conversations-and-routing`: group, mention, file, and direct paths.

The theme labels are pinned to VitePress text/background tokens, and node label
line-height is pinned to 1.2 so the Mermaid geometry does not clip text. The
architecture edge direction was changed to `server -> config` to separate its
label from the storage edge.

## Limitations and not run

- No screen-reader pass (NVDA, VoiceOver, Orca), no real mobile device, and no
  Safari or Firefox run. The browser audit used headless Chromium against the
  local VitePress preview only, not the user's browser.
- No macOS/Herdr run and no real installed-package run. The docs page and
  assets are Linux outputs.
- The replay is not a clean public-registry install and is not a live
  `asciinema rec`. Install output is not claimed.
- The screenshots show the synthetic fake provider/model labels and fixture
  content. They are not customer data or a hosted service.
- VitePress reports a client-chunk size warning from the Mermaid bundle. It is
  a local, lazily loaded asset; no external analytics or runtime service was
  added.
- Long playback performance, audio, and a screen-reader-only terminal-player
  path were not measured. The page supplies a text summary of the replay as the
  accessible equivalent.
