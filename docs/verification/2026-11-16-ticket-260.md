## What changed

- `src/v2/latency-budget.ts` is the pure evaluator. It owns the reference and
  smoke profiles, nearest-rank percentiles, per-metric gate/report decisions,
  and the formatted report. First-token is always report-only.
- `src/v2/latency-budget.test.ts` covers the percentiles, pass/fail at each
  threshold, missing/invalid samples, the smoke profile, report-only
  first-token, the report profile, and a deliberate regression.
- `scripts/lib/latency-driver.mjs` is the deterministic patch-card fixture. It
  invokes `task.delegate`, reads the durable `changes.since` patch after that
  version, applies the subtask changes to a client-side state map, and renders
  the real `workCardForTask` mapping. It never waits for a model token, so the
  fake provider's hold cannot dominate the card number.
- `scripts/latency-budget.mjs` evaluates a saved result with the pure
  evaluator and exits nonzero on a budget failure.
- `scripts/live-latency-probe.sh` reports three metrics separately: gated rail
  keypress p95, gated patch-card p95, and report-only first-token. The default
  profile is the generous `smoke` PR threshold; the reference profile enforces
  50 ms / 250 ms. `ENSEMBLE_LATENCY_REGRESSION_MS` injects a deliberate
  regression. The result JSON goes to `ENSEMBLE_LATENCY_OUT` for CI artifacts.
- `.github/workflows/latency.yml` runs the smoke profile on pull requests and
  the reference profile nightly. `npm run verify` runs the pure evaluator on
  every PR; `npm run test:live:latency:reference` is the documented reference
  gate.
- `package.json` adds `test:live:latency:reference` and `latency:budget`.

No TUI layout or behavior changed. The probe reuses the #256 harness
readiness/artifact helpers and classifies rail/first-token wait timeouts as
timing failures; a budget failure is a product failure and never retries.

## Baseline and thresholds

Measured on the reference host (Linux, Node 26.12.1, OpenCode 2.2.7, tmux,
140x50 TUI):

| Metric | Samples (ms) | p50 | p95 | Reference budget |
| --- | --- | --- | --- | --- |
| `rail` | 9, 9, 9, 9, 9, 9, 9, 10, 9, 9 | 9 | 10 | 50 |
| `patchCard` | 36, 32, 33, 31, 33 | 33 | 36 | 250 |
| `firstToken` | 672 | 672 | 672 | report only |

The earlier tmux card-appearance number (~1.9 s p50) was dominated by the
client feed path and the fake model hold; it is not the patch-card budget
metric. The deterministic fixture measures the RPC -> durable patch -> real
card render path directly and leaves the TUI capture out of the gate.

## Reference gate policy

- PRs: `npm run verify` (pure evaluator) and the `smoke` live job (rail 500 ms,
  patch-card 5000 ms). The smoke thresholds are generous because a shared PR
  runner is not a reference host.
- Reference host/nightly: `npm run test:live:latency:reference` (rail 50 ms,
  patch-card 250 ms). The nightly workflow pins Node 26.12.1 and OpenCode
  2.2.7 and runs the preflight first.
- Local measurement without a gate: `ENSEMBLE_LATENCY_PROFILE=report npm run
  test:live:latency`.
- Deliberate regression: `ENSEMBLE_LATENCY_PROFILE=reference
  ENSEMBLE_LATENCY_REGRESSION_MS=1000 npm run test:live:latency` exits 1.
