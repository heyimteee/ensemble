# Ticket #261: full deterministic E2E in CI — verification

- **Branch:** `ticket/261-ci-matrix`
- **Base:** `integration/prod-partials` (`4a84aa8`, merge of #260)
- **Spec:** #255, ticket #261
- **Host:** Linux/tmux, Node 26.12.1, npm 12.2.1, OpenCode 2.2.7, tmux 3.5a, fd 10.2.0
- **Gate:** `npm run verify` (typecheck + unit suite), `npm run docs:check`

## What changed

- `verify.yml` is split by cost into `verify`, `live-fake`, `live-native`,
  `live-multilocation`, and `latency-smoke`. Every live job runs in parallel,
  sets `ENSEMBLE_LIVE_REQUIRE=1`, writes redacted artifacts to
  `$RUNNER_TEMP/ensemble-live-artifacts`, and uploads them on failure. The
  workflow has a `concurrency` group that cancels superseded PR runs.
- `nightly.yml` owns `latency-reference` (the strict 50/250 ms profile) and
  `real` (`test:live` with the real host catalog). The real job is opt-in via
  the `real` dispatch input or `ENSEMBLE_NIGHTLY_REAL=1`; the schedule is
  `17 4 * * *` with `workflow_dispatch` available.
- `.github/actions/live-host/action.yml` installs the pinned toolset once:
  Node, tmux, fd 10.2.0, OpenCode from the input version, and `npm ci`. Every
  live job in both workflows uses it, so the host pin cannot drift job by job.
- `verify.yml` pins OpenCode 2.2.7, the latest host in
  `SUPPORTED_OPENCODE_VERSIONS`; `compatibility.yml` continues to run 2.2.6 and
  2.2.7. The old `latency.yml` is removed: the smoke profile is in `verify.yml`
  and the reference gate is in `nightly.yml`.
- `src/v2/ci-workflows.ts` is the pure job-graph checker. It owns the job
  budgets, suite ownership, host-pin check, and repository check.
  `src/v2/ci-workflows.test.ts` mutates workflow text to prove a missing suite,
  a duplicated suite, a missing require mode, a missing artifact upload, an
  over-budget or missing timeout, a stale host pin, a missing concurrency
  block, a non-reference nightly profile, a non-opt-in real job, a PR-triggered
  nightly workflow, and a hardcoded action version all fail.
- `scripts/live-lifecycle-fake.sh` now matches the compact Work header
  (`WORK ACTIVE │ N group(s) · N active`) introduced by #263's 53-column
  card-mode floor. This is a test-harness assertion fix, not a product change;
  the group label still carries the active/done counts.

No product behavior changed. The skip-versus-fail contract is unchanged:
local prerequisites skip, `ENSEMBLE_LIVE_REQUIRE=1` turns a skip into a
failure, and only a classified timing failure may retry once.

## First attempt

The first `test:live:lifecycle` run failed after 20 s waiting for
`WORK ACTIVE │ 1 group · 1 active · 0 done`. The captured pane showed the
compact post-#263 header (`WORK ACTIVE │ 1 group · 1 active │ page 1/1`) with
the group label `GROUP 1 · 1 active · 0 done` directly below. The assertion
expected the pre-#263 full header. The harness now matches the common prefix;
the rerun passed in 334 s. No product code or layout changed.
