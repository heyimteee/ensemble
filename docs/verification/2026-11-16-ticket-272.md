# Ticket #272: data retention, export, delete, and roster disclosure

Parent: #268. Scope: give users control of their Ensemble data, document the
retention policy, provide a user-facing export and delete path, and disclose the
v7 `AGENTS.md` roster title/role write. No new product feature beyond data
control and privacy disclosure.

## What shipped

- **Data classes and retention policy.** `docs/privacy/data-and-retention.md`
  documents conversations/messages, Work, memories, approvals and queued direct
  sends, bindings, host native sessions, attachments, workspace config, the
  generated `AGENTS.md` block, logs, and settings. It cites the enforced values:
  terminal Work (including finished native-subagent rows) is purged 24 hours
  after it finishes (`FINISHED_RETENTION_MS`), and local logs keep 7 days, 5
  rotated files per prefix, and 10 MiB per file by default. Conversation and
  memory rows have no automatic expiry.
- **Export.** The existing `ensemble.v2` RPC gained `data.export`. The
  projection lives in `src/v2/data-control.ts`, format
  `ensemble.data-export` / `formatVersion: 1`, documented with a field-by-field
  example. It carries the workspace roster, group and direct conversations,
  message text and attachment metadata, Work text, and workspace-attributed
  memories. It never carries binding session ids, workspace or home directory
  paths, model configuration, settings, credentials, operational logs, other
  workspaces, or agent-global memories.
- **Delete.** `data.delete` (confirmation `DELETE`) stops active init and Work
  for one workspace, removes its conversations/messages, Work, dispatch groups,
  init jobs, native-subagent rows, workspace memories, approvals, queued direct
  sends, workspace/direct bindings, and attachment bytes. The workspace row,
  roster, and `.ensemble/config.json` stay, so the workspace remains usable and
  the next turn starts a fresh native session. Host native sessions are removed
  only with `--delete-native-sessions`.
- **User-facing path.** `npm run data -- export|delete` is a doctor-style CLI
  over the same `invoke` RPC and service descriptor. It adds no runtime seam.
- **Log control.** `LOG_RETENTION_DAYS`, `LOG_MAX_FILES`, and `LOG_MAX_BYTES`
  are exported and used by the logger defaults; `purgeLogFiles()` deletes only
  Ensemble-owned JSONL names. `data.delete --logs` uses it. The export reports
  the retention values and excludes the logs themselves.
- **Roster disclosure.** The v7 roster writes names, titles, and roles into
  `AGENTS.md` at init and on config reconciliation. The privacy document
  explains what is written, when, the public-repository risk, and the guidance
  (keep title/role non-sensitive or empty before init). The supported opt-out is
  manual: remove the whole `ensemble:start` block and `.ensemble/init.json`
  (which marks the directory initialized), and do not re-run workspace init.
  No config switch was added: it would change the v7 contract and the
  workspace-config schema, which is wider than this ticket and destabilizes the
  contract.

## Boundaries and known limits

- Ensemble deletes its own durable rows. The OpenCode host owns native session
  transcripts; they survive unless `--delete-native-sessions` is passed, and the
  host may still retain its own copies.
- Removing the binding is what prevents re-ingestion after delete. Without it,
  the next start-time reconcile could recreate deleted messages from the host
  context.
- A per-workspace export/delete does not touch agent-global memories or
  `ensemble.reset`-only rows (settings and UI state).
- `AGENTS.md` removal is manual and repository-owned; reconciliation rewrites
  an initialized workspace's block, so the opt-out requires removing
  `.ensemble/init.json` and not re-running init.
