## Scope

This record covers the repo-side release contract: the protected default
branch, the tag-driven workflow with a token-free dry run, npm provenance and
the CycloneDX SBOM, the changelog-based GitHub release, and the release
sign-off checklist. It does not publish to the public npm registry, use a real
npm credential, or create a tag. The final `0.1.0` notes and launch sign-off
belong to #278; macOS/Herdr belongs to #277.

## Release workflow

`.github/workflows/release.yml` is the only publishing path:

| Trigger | Mode | Result |
|---|---|---|
| `push` tag `v*` | Real release | Preflight, package, provenance publish, GitHub release |
| `workflow_dispatch` | Dry run (always) | Preflight, package, `npm publish --dry-run`; no secret, no publish |
| Branch push or pull request | Not triggered | No job can reach the publish step |

- `release-preflight` validates the tag against `package.json`, extracts the
  changelog section into `RELEASE_NOTES.md`, and exports `version`, `tag`,
  `dry-run`, and `dist-tag`.
- `package` runs `npm ci`, `npm run verify`, `npm run docs:check`,
  `npm run build`, `npm pack`, and `npm sbom --sbom-format=cyclonedx
  --package-lock-only`, then uploads the tarball, SBOM, and pack report.
- `publish-dry-run` uses `npm publish --dry-run --access public --tag
  "$DIST_TAG"` and has no `secrets.` reference.
- `publish` is gated to a tag push, grants `id-token: write`, reads
  `NODE_AUTH_TOKEN` from `secrets.NPM_TOKEN`, and runs
  `npm publish --provenance --access public --tag "$DIST_TAG"`.
- `github-release` is gated to a tag push, grants `contents: write`, and creates
  the release from `RELEASE_NOTES.md` with the SBOM, tarball, notes, and
  `CHANGELOG.md` attached.
- A prerelease publishes under `next`; a final release publishes under
  `latest`. npm refuses a prerelease without an explicit tag, which the first
  dry run exposed; the preflight now supplies it.

`CHANGELOG.md` is the release-notes source. A version without a non-empty
section fails the preflight, so notes cannot be generated from commit messages.
`docs/operations/release.md` records the process, credential boundary, and
protection; `docs/operations/release-signoff.md` covers security, MIT
license/legal, package contents, rollback, support readiness, and the
clean-install proof.

## Residual risks

- The required checks include the long `live-fake` suite. A red suite blocks a
  merge until it is fixed or the documented admin bypass is used.
- The repository is maintained by one account, so the one-approval rule cannot
  be satisfied without the explicit admin bypass. Bypass use belongs in the
  sign-off.
- `NPM_TOKEN` must exist before the first tag. Without it the publish job fails
  safely before any upload.
- The SBOM is built from the lockfile and therefore includes locked development
  dependencies as well as runtime dependencies. That is conservative for an
  artifact SBOM; it is not a claim that dev packages ship.
- A failed publish leaves the tag; fix forward with a new patch version rather
  than moving a published tag.
- The first GitHub-hosted run is the first real execution of the workflow. The
  dry-run dispatch should be run immediately after this branch reaches the
  default branch and before the release tag.
