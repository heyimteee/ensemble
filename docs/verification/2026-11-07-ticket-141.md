## Tier 3 gate decision

`src/v2/scoped-read.ts` is the only gate policy. Scoped bootstrap/projection
engages when any of:

- durable messages >= 1,000,
- retained task rows >= 500,
- the last measured full snapshot payload >= 512 KiB,
- the last measured full snapshot build >= 120 ms.

Small workspaces keep the full snapshot path; the response records the gate,
its reason, and its measured inputs. Epoch changes, malformed feeds, and a
failed scoped read still fall back to the full snapshot.

## Scoped recovery

The store records the latest version that changed `shell`, `work`, and
`transcript`. A gap calls `changes.since`, derives only the scopes with a
version newer than the client cursor, and calls `resync` with exactly those
scopes. The service test proves a work-only gap returns no shell or
transcript payload, and a shell/transcript gap returns no Work payload.

## Residual risks

- Unread/busy counts are recalculated on the revision heartbeat, bootstrap,
  and scoped resync rather than on every patch; the rail may trail a live
  message by up to one heartbeat (1 s active, 2 s idle).
- Older transcript pages are fetched by keyboard scrolling (PageUp/Top and
  scroll-up keys). Mouse-wheel pagination is not wired through the host
  scrollbox API.
- Client windows keep the newest 240 rows; paging far back can evict the
  newest rows until the next latest-window refresh.
- macOS/Herdr checks remain for #143.
