## What changed

- The wizard alignment check waits for step readiness (`live_require_ready_text`)
  and the typed field value (`live_type`) before Enter. Fixed sleeps around
  wizard transitions were removed; Enter is always a separate input event.
- `live_type` observes the last four non-space characters of the typed text
  plus a pane change, so a wrapped long line still proves the field committed.
- `scripts/live-matrix.sh` classifies a failed attempt from the harness
  `failure.json` record. Only a `timing` failure retries, once. Product,
  unknown, and infrastructure failures never retry. Skips keep the existing
  local-skip / require-mode-fail contract.
- The harness writes redacted pane captures, logs, `failure.json`, and
  `failure.txt` under `ENSEMBLE_LIVE_ARTIFACTS` on failure. CI uploads the
  directory.
- `scripts/flake-quarantine.json` entries require a linked issue and an owner;
  the matrix refuses to start with an invalid entry.
- `src/v2/flake-policy.ts` owns the pure classifier, retry decision, quarantine
  validation, and report. `src/v2/flake-policy.test.ts` and
  `src/v2/live-matrix.test.ts` cover the policy and the matrix loop with stub
  scenarios.
- The mixed-anchor assignment check reads the durable system message instead of
  the visible chat cell: a long streamed reply can scroll the older assignment
  line out of the viewport even though routing is correct. The Work rows,
  replies, and exact instruction remain asserted separately.
- Header assertions use the compact `#263` prefix (`… · N active`) because the
  merged three-pane width may drop the `done` segment while keeping the page
  and counts.
