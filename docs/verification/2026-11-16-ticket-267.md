## Scope

The first PR run exposed three CI-only failures. This record covers the
test/docs fixes; it does not change product behavior.

## Fixes

### Docs index

`docs:check` rejected the new `2026-11-16-prod-partials-e2e.md` record because
it was not linked. `docs/README.md` now links it and this record.

### Skill validation probe

`live-check-fake.sh` typed the wrong-owner message, pressed Escape, checked
that the completion hints were gone, and pressed Enter within 10 s. Under CI
load the Escape could be consumed by a completion that was still opening, and
Enter could then select a completion row instead of submitting. The draft
survived unchanged and no validation message appeared, so the product
assertion failed.

The probe now calls `live_settle_composer_insert`: it closes any completion,
waits for the composer's Normal status, returns to Insert, and only then
submits. Those readiness waits are timing-classified. The validation assertion
keeps a 30 s window for a slow host and stays a product assertion. The draft
and zero-work assertions are unchanged.

### Reduced-motion compatibility check

The reduced-motion loop grepped the whole pane for non-zero motion glyphs.
OpenCode 2.2.6 draws its own footer spinner (`⠏ Finishing startup…`) while the
Ensemble Work card is correctly pinned to `⠋`. The check now asserts
Ensemble-owned surfaces only: the Work card header and the rail busy mark must
stay on frame 0, and no later frame may replace either. Host chrome is excluded
from the assertion, not from the compatibility smoke.

`src/v2/live-matrix.test.ts` adds a fixture test proving a host footer spinner
does not fail the check while an animated Work card or rail still does.
