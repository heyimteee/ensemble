## Re-verification method (2026-11-16/17)

The three fixed failures were re-checked **without any screen access** while the
user was on a video call:

- Host access was SSH only. Commands ran in a **detached tmux session** on a
  private socket (`tmux -L ensemble277`) at 140×50. Nothing was attached to the
  user's terminal, tabs, or frontmost app.
- The TUI was read with `tmux capture-pane -p` (text) and
  `tmux capture-pane -p -e` (text + ANSI). State came from the isolated
  service's RPC snapshot and from filesystem reads.
- **No screenshots of any kind** were taken (`screencapture` was not run and no
  image file was created), **no AppleScript / System Events / `osascript`** was
  used, **no Herdr command** was issued, and **no pointer or mouse input** was
  sent. There were no focus changes and no keystrokes to the frontmost app.
  Keys went only to the detached pane (`tmux send-keys`).
- The user's OpenCode config, service, clipboard, and processes were not
  touched. The previous isolated HOME/XDG roots were reused; the installed
  package cache was refreshed from the branch build at `70f3da7` with
  `npm pack`, the loopback registry, and `opencode plugin add`. The server log
  loads `dist/server.js` from the isolated package cache. The candidate was
  507,243 bytes with 121 built JS files.
- `tmux` stores colors as 256-color indices; the terminal-default intent
  (`39`/`49`) survives unchanged, and the sequences quoted below are the ones
  `capture-pane` recorded before the terminal applied them.

The first-pass method below is historical. It used Ghostty AppleScript and

## Fake E2E and size matrix

From a clone of tag `rc-0.1.0-rc.2` with the fixes on this branch:

```sh
ENSEMBLE_LIVE_REQUIRE=1 bash scripts/live-check-fake.sh           # PASS
ENSEMBLE_LIVE_REQUIRE=1 bash scripts/live-check-fake-empty.sh     # PASS
ENSEMBLE_LIVE_REQUIRE=1 ENSEMBLE_V6_SKIP_LOAD=1 \
  bash scripts/live-size-matrix.sh                                 # PASS
```

The first full fake attempts failed at the doctor check with an empty output.
Root cause: `doctor-cli.ts` compared `import.meta.url` with the raw
`process.argv[1]` path; on macOS `/tmp` is a symlink to `/private/tmp`, Node
resolved the module URL to the real path, the guard was false, and the CLI exited
0 without running `main()`. The fix compares real paths and adds a symlink
regression test (`src/v2/doctor-cli.test.ts`). The live harness also
canonicalizes its isolated base path with `pwd -P` so host-reported paths compare
equal under the macOS `/var` symlink.

## Follow-ups

Fixed and re-verified with no open follow-up: 4.6b (#281), 8.2 (#282 and #284), and 9.8 (#283).

1. **OpenCode 2.2.7 Git installs fail upstream.** `github:`, `git+https://…`, and

   sent to `opencode`. This is not Ensemble-specific; do not recommend Git
   installs. Use the npm package or the loopback registry.
2. **Herdr prefix ownership remains inconclusive host-level evidence**, not a
   checklist FAIL. The independent re-test with `ctrl+s`, `ctrl+a`, and `ctrl+b`
   + `c`, after `herdr server reload-config`, Ghostty frontmost, and real
   System Events keystrokes produced no tab or pane; none of Ensemble's

3. **1.7 mouse selection is PASS; automatic copy-on-release is a host note.**
   The real Herdr/Ghostty session used Shift+drag and an explicit
   `copy_to_clipboard`; mode/focus stayed unchanged. Ghostty `copy-on-select` is
   off, so a drag alone does not copy and automatic copy-on-release is not

4. **Size-matrix load probe** is Linux `/proc`-only; the exact sizes pass with
   `ENSEMBLE_V6_SKIP_LOAD=1`, but the load probe is not measured on macOS.
5. **Braille font coverage.** The configured face has no Braille codepoints;
   the terminal fallback rendered the glyph. Add a Braille-capable font to the
   host requirements or state the fallback dependency.
