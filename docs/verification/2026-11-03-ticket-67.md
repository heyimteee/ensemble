# Verification — ticket #67 (chat bubbles, muted inline completions, unified attribution)

Date: 2026-11-03 · Worktree: `/tmp/opencode/ensemble-worktrees/55-67-bubbles` · Branch: `feat/v55-67`
Base: `e0f6d5c` (integration tip unchanged at verification time — nothing to merge).

## What changed

- `src/v2/tui/bubbles.ts` (new): pure ticket-#67 seam. Bubble layout
  (`BUBBLE_WIDTH_RATIO = 0.72`, `bubbleWidth`, `bubbleContentWidth`,
  `bubbleSide`, `isBubbledRole`), unified author grammar
  (`relayPartiesForTask`, `relayHeader`, `bubbleHead`,
  `unifiedAuthorColor`), and inline completions (`completionEntry`,
  `accumulateCompletions`, `mergeTranscriptRows` over the shared
  40-row `TRANSCRIPT_WINDOW`).
- `src/v2/tui/bubbles.test.ts` (new, 8 tests): width bound, side mapping,
  relay headers naming answerer + asker (`Answer from $Nova · for $Sage`,
  `· for you` for user asks), one color source for ID- and name-resolved
  agents, completion finish-time/`done:` IDs, accumulator persistence with
  no regeneration, merged order/window/dedup.
- `src/v2/tui/workrows.ts`: `ActivityEntry` gains optional `agentID` (set
  from `task.assigneeID`) so activity lines resolve through the same color
  source; no shape change for existing callers/tests.
- `src/v2/tui/app.tsx`:
  - Transcript renders one merged row list: agent bubbles left-aligned in
    filled `panel` blocks with `border={["left"]}` in the agent color;
    user bubbles right-aligned (`alignSelf: flex-end`, `width: 72%`);
    system/task/approval/assignment/completion rows full-width, unbubbled.
    Inner text paints the bubble fill; wrap width is the bounded bubble
    width. No per-message timestamps (unchanged).
  - Terminal outcomes persist via a `completionMap` accumulator (one entry
    per task ID, never regenerated) merged into the transcript at finish
    position. The derived trailing `workAnnouncements` feed is removed.
  - Headers go through `bubbleHead`/`relayPartiesForTask`: relayed answers
    read `Answer from $Answerer · for $Asker|you`. Colors go through
    `unifiedAuthorColor` for transcript rows and activity/queued lines.
  - Back-to-bottom control is a bare `↓` glyph (no border, no words); `End`
    binding and scroll/sync behavior untouched. Scrollbox identity,
    sticky-bottom, live/finalized partition, stagger, WORK/activity/DM/
    wizard/dialog/`$Name` routing preserved.
- `scripts/live-check-fake.sh`: bubble layout anchors (deep space run
  before user text; `│ │ │` accent edge before agent reply), inline-order
  anchor (first completion line precedes `peer-check`), bare-`↓` anchors
  (`↓` present scrolled-up; `↓ bottom` / `bottom · end` absent; `End`
  restores). The old `count == 5` trailing-feed assertion became a
  tail-presence + snapshot-terminal-total (`== 5`) pair, since inline
  completions scroll with the conversation.

## Uncertainty / notes

- One `test:live:fake` run failed transiently at the pre-existing DM
  "link text" assert (markdown native layout vs assert race: reply body
  rows not yet populated in that capture); the immediate rerun passed
  fully with no code change, and a further full pass confirmed. Not
  attributed to ticket-#67 geometry, but flagged: the DM fixture asserts
  assume the whole tall reply fits the 80-row viewport at once.
- Text capture cannot see fills or border colors: bubbles are proven by
  structure (right indent run ≥ 15 for user text; `│ │ │` rail/chat/edge
  prefix on agent replies), not pixels. Accent hue agreement is by
  construction (single `unifiedAuthorColor` source + unit pin).
- `border={[]}` for user bubbles relies on OpenTUI treating an empty side
  list as no border; observed working in all live runs (no crash, right
  indent with no edge glyph).
- Completions are TUI-side persisted (accumulator keyed by task ID),
  ordered by `finishedAt ?? repliedAt ?? createdAt`; service write path
  untouched, 24 h retention semantics unchanged.
