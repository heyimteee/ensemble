## Contract v6

`ENSEMBLE_BLOCK_VERSION = 6`. The workspace `AGENTS.md` block now states the
native-first rules:

- the final native text is the group message;
- `$Name` routes work, a bare name is only a reference, and `@path` is
  file-only;
- code spans, URLs, and paths never route;
- direct conversations are one-to-one;
- the server owns routing, budgets, and completion;
- do not claim a teammate replied until their turn is visible, and do not open a
  second completion loop for a teammate you asked;
- explicit `ensemble_delegate` and `ensemble_handoff` are migration and rollback
  tools, not the normal chat path.

The old “every non-leader turn ends with a handoff” rule is removed. The
repository handoff contract and root agent instructions were updated to match.

## Roster table

The block carries one generated `Team roster` table:

| Member | Title | Role |
|---|---|---|
| **Ada** (leader) | Lead Engineer | Own architecture and release. |
| Bo | Researcher | Own evidence. |
| Cy | Analyst | Own metrics. |

- Active members only; archived members are excluded.
- The leader is first and marked `**Name** (leader)`.
- Remaining members follow `memberIDs` order.
- `Title` and `Role` are the stored strings exactly as authored.
- Only table syntax is escaped: `|` becomes `\|` and a newline becomes `<br>`.
  No other rewriting, truncation, or summarization.
- The generic identity block and every `ensemble_turn` block stay unchanged;
  the table is written once to the workspace file, not per turn.
- Rows contain names, titles, and roles only: no credentials, conversation
  content, or private paths.

## Refresh and reconciliation

`reconcileEnsembleInstructions` compares the desired block text as well as the
version marker, so a roster change rewrites the block at the same version.
Project-owned content outside the Ensemble markers is preserved, and a newer
recorded version is never downgraded. Refresh triggers:

| Change | Service path |
|---|---|
| Workspace membership or leader | `workspace.update` and config/discovery reconciliation |
| Workspace creation | `workspace.create` and discovery |
| Agent name, title, or role | `agent.update` |
| Agent archive | `agent.archive` |
| Agent delete | `agent.delete` |
| Version or content drift | Maintenance and start reconciliation |
