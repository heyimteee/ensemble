## Behavior

The native-first path now treats the final native text as the group message and
`$Name` as the routing operator. A workspace native user message or agent final
text routes normal peer turns with server-assigned budgets; the explicit
`send_message` tool is no longer part of that path. The service injects one
compact `ensemble_turn` block each native turn with the roster, conversation,
and dispatch-budget numbers, so an agent does not call read-only roster tools.

The `send_message`, `workspace_info`, `list_workspaces`, and `list_agents`
tools remain only on the legacy surface (and `send_message` is described there
as a compatibility shim). `delegate` and `handoff` also stay on that surface
until the native path has live loop and budget evidence. The decision tools
remain on both surfaces: `task_status`, `review`, `ask_person`, `remember`, and
`share`.

## Flag and rollback

- `nativeFirst: "on"` selects the native surface; `off` and `shadow` keep the
  explicit surface.
- `settings.toolSurface: "native" | "legacy"` is a validated override for one
  release. It is the rollback path and is accepted even while native ingestion
  is on, so an operator can restore the old tools without rolling back durable
  ingestion.
- A surface change disposes and re-registers the tool transform for every
  attached host location; it does not wait for a restart.
- Rolling back never deletes durable messages, native turns, bindings, dispatch
  groups, or Work history.
