## Delivered

- [Support policy](../support/README.md): GitHub Issues channel, private
  security route, best-effort response targets, evidence checklist, and the
  redaction rules.
- [Incident runbook](../support/incident-runbook.md): severity, symptom guide,
  diagnostics (`doctor`, `:logs`, log summary, host log), evidence bundle,
  package rollback, disable-without-uninstall, data recovery, escalation, and
  post-incident follow-up.
- [Support matrix and known limitations](../support/support-matrix.md):
  Linux/tmux support, macOS/Herdr **unverified** pending #277, Windows out of
  scope, OpenCode 2.2.6/2.2.7, Node 22.23.4/24.22.1/26.12.1, terminal sizes,
  and live-suite prerequisites.
- [Bug report](../../.github/ISSUE_TEMPLATE/bug.yml) and
  [support request](../../.github/ISSUE_TEMPLATE/question.yml) issue forms plus
  [issue chooser config](../../.github/ISSUE_TEMPLATE/config.yml), and the
  [pull-request template](../../.github/PULL_REQUEST_TEMPLATE.md). Every intake
  form collects versions, install method, commands, evidence, and redacted
  diagnostics, and forbids credentials and conversation content.
- README and documentation index links to the support path.
- `docs:check` now requires the support hub, runbook, matrix, issue forms, and
  PR template, the README/index links, and the redaction warning.
