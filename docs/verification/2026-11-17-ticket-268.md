## Live TUI readiness (#287)

#287 merged at `a7f1eb3` and is closed. The root cause was a harness false
positive, not lost input: after Backspace the command line was `:setting`;
retyping `s` restored the previous `:settings` pane, so `live_type` saw no
pane change and reported `typed text did not reach the TUI: s`. The fix waits
for `:settings` to disappear before retyping and gates input on a rendered
statusline. `live_open_ensemble` now forces the configured geometry and waits
for the statusline before returning. There is no product runtime change, and
the fix is covered by 2,121 tests.

## What is pending or not claimed

1. **A real package downgrade** has not been rehearsed, because there is no
   previous public version. State rollback is rehearsed. This is the only
   inherent release gap.
2. **The launch announcement** has not been made. It is a separate decision;
   the release itself is published.
3. **The prerelease owns npm `latest`.** Both `latest` and `next` point at
   `0.1.0-rc.2` because it is the only version. npm requires `latest` and
   rejects deleting it (E400). Pin the exact version; a stable release will
   move `latest`.
4. **Automatic copy-on-release is not claimed.** The 1.7 mouse pass used
   Shift+drag plus explicit copy; Ghostty `copy-on-select` is off. This is a
   host preference, not Ensemble behavior.
5. **macOS/Herdr on OpenCode 2.3.0 is not claimed.** macOS/Herdr is verified on
   2.2.7 only; the 2.3.0 support claim is Linux-verified.
6. **Herdr prefix ownership** is inconclusive host evidence, not a checklist
   FAIL. No Ensemble key was observed to be intercepted.
7. **Git-spec installs** fail upstream in OpenCode 2.2.7 during Git dependency
   preparation. Use the npm package.
8. **Windows and WSL** are out of scope and untested.
9. **macOS size-matrix load probe** is Linux `/proc`-only. Exact sizes pass with
   the load probe skipped; Braille rendering depends on terminal font fallback.
10. **No telemetry** is claimed. Diagnostics are local and must be redacted
