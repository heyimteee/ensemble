### Live defect found and fixed in this pass

The live gap-recovery path exposed one real integration defect: an HTTP
`changes.since` response returned **500 `rpc.invalid_output`** at
`entries[0].entities[0].message` because a message entity carried explicit
`undefined` optional fields (`agentID`, `updatedAt`, and peers). The TUI caught
the error and fell back to a full snapshot, so no data was lost, but the
intended cheap gap path was unusable.

Fixed in `src/v2/service.ts`: `changesSince` now applies the same JSON
sanitization as the snapshot/bootstrap boundaries. Regression coverage lives in
`src/v2/service.test.ts` (`changes.since output stays JSON-safe at the RPC
boundary`), which walks the handler response for explicit undefined values. A
live probe against OpenCode 2.2.6 now returns **200** with contiguous entries
and the expected message/subtask/workspace/agent entities.

## Large-history bootstrap, client memory, and Tier 3 gate

The large-history test seeds **10,000 durable messages** and **602 retained
tasks** (600 long-terminal rows plus one visible group), then calls the scoped
bootstrap handler over durable storage:

| Measure | Observed | Budget |
|---|---:|---:|
| Bootstrap payload | **26,379 B** | < 128 KiB |
| Bootstrap latency | **11.7 ms** | < 500 ms |
| Transcript rows in payload | 40 | one active window |
| Work rows in payload | 2 | visible group only |
| Tier 3 gate | enabled (`messages >= 1000`) | recorded with inputs |

The client-memory benchmark applies **5,000 message patches** plus **1,000
invisible terminal tasks**:

| Measure | Observed | Budget |
|---|---:|---:|
| Loaded message rows | **240** | `CLIENT_MESSAGE_LIMIT` (240) |
| Loaded Work rows | 1 (active) | visible projection |
| 5,000 patch applications | **109.1 ms** | < 5,000 ms |

**Tier 3 gate decision: enabled for the measured large workspace and left
disabled for small workspaces.** `src/v2/scoped-read.ts` is the single policy
source: history ≥ 1,000 messages, retained tasks ≥ 500, last snapshot payload ≥
512 KiB, or last snapshot build ≥ 120 ms. The response carries `gate`,
`scoped`, `counts`, `window`, and `scopeVersions`; a disabled gate keeps the
full snapshot path. The scoped path remains a disposable read model over
durable storage, never a new authority.
