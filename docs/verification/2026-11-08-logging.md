# Structured logging (#145)

Status: **verified locally on Linux/tmux; macOS/Herdr unexecuted**
Date: 2026-11-08

Base: `integration/ensemble-v7` at `e6b6f06`
Branch: `feat/v7-logging`

This record covers the operational logging layer:

- One dependency-free logger with `error`/`warn`/`info`/`debug`/`trace`
  levels and service/task/retry/approval/message/feed/refresh/tui/host/failure
  categories.
- A bounded 2,000-entry ring for live inspection plus per-process rotating
  JSONL sinks and a longer-retention failure sink.
- Store observers for task, message, approval, and init lifecycle events.
  Lease heartbeats and stream checkpoints never create lines.
- Self-contained failure records for each attempt, uncertain park, and
  terminal failure, including the error chain/stack, provider/model, run and
  session IDs, tool outcomes, recent message metadata, and the decision.
- `logs.recent`, `:logs`, `:logs failures`, and `:logs task <id>`.
- Content logging off by default; secrets redacted; files `0600` in a `0700`
  directory.
- Asynchronous, batched writes with drop counters; write failures never fail
  work.

### Sample failure record

The failure sink writes one JSON object per line. The core fields are:

```json
{
  "ts": "2026-11-08T11:06:40.000Z",
  "level": "error",
  "cat": "failure",
  "event": "failure.terminal",
  "incidentID": "failure_...",
  "failureClass": "provider",
  "taskID": "t_1",
  "workspaceID": "w_1",
  "dispatchGroupID": "g_1",
  "title": "Fix parser",
  "attempts": 5,
  "error": {
    "name": "Error",
    "message": "quota exhausted",
    "code": "E_PROVIDER",
    "stack": "Error: quota exhausted …"
  },
  "model": { "providerID": "openai", "modelID": "gpt" },
  "runID": "run_1",
  "sessionID": "ses_1",
  "toolOutcomes": [{ "name": "bash", "status": "failed", "error": "exit 1" }],
  "lastMessages": [{ "messageID": "m_1", "author": "agent", "kind": "text", "chars": 12 }],
  "decision": { "type": "terminal", "reason": "attempts-exhausted", "attempt": 5, "maxAttempts": 5 },
  "version": 42,
  "epoch": 7
}
```

Task text, constraints, expected output, and message text are absent unless
`ENSEMBLE_LOG_CONTENT=1`.

## Operational notes

- Service and TUI files are per-process (`<role>-<date>-<pid>.jsonl`), so a
  rotating sink is never shared across processes.
- Main logs retain 10 MB × 5 files for 7 days; failure logs retain 20 MB × 5
  files for 30 days.
- Tests keep the ring but skip file sinks unless a test supplies an explicit
  directory, so `npm test` never writes into the user's state directory.
- The logger drains every batch on `close()`; a shutdown cannot strand the
  tail of a burst.
